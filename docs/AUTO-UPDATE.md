# Автообновление (electron-updater)

Приложение при запуске проверяет наличие новой версии и, если есть, скачивает её в фоне. Когда обновление готово — вверху появляется баннер **«Обновление X.Y.Z загружено → Перезапустить и установить»**. Также есть ручная кнопка в **Настройки → Обновления**.

## Как это работает

- Провайдер — **generic** (обычный HTTP), URL задан в `package.json → build.publish`:
  ```json
  "publish": [{ "provider": "generic", "url": "http://192.168.18.232:8090/updates/" }]
  ```
- На старте приложение читает **`<url>/latest.yml`**, сравнивает версию с установленной, качает новый `Setup.exe` (по blockmap — только изменившиеся куски) и ставит при перезапуске.
- В **dev-режиме** (`npm start`) обновления отключены — работают только в **установленной** версии.

## Как выпустить новую версию

1. Подними версию в `package.json`:
   ```
   "version": "0.1.1"
   ```
2. Собери:
   ```
   npm run dist
   ```
3. Скопируй из папки `dist\` в каталог, который отдаётся по URL публикации:
   - `latest.yml`
   - `1C-DevOps-Studio-Setup-0.1.1.exe`
   - `1C-DevOps-Studio-Setup-0.1.1.exe.blockmap`
4. Всё. У пользователей при следующем запуске появится баннер обновления.

## Настройка «сервера обновлений»

Нужен любой каталог, отдаваемый по HTTP по адресу из `publish.url`. Варианты:

- **Твой Apache** (`192.168.18.232:8090`) — добавь alias/каталог `updates` и клади туда файлы из шага 3. Тогда `publish.url = http://192.168.18.232:8090/updates/`.
- Любой другой внутренний веб-сервер / nginx / IIS — просто статическая раздача папки.
- (Опц.) Публикацию можно автоматизировать: `electron-builder --publish always` при настроенном провайдере.

Если URL сменится — поправь `build.publish.url` в `package.json` и **пересобери** (URL зашивается в приложение при сборке, в `resources/app-update.yml`).

## Проверка

1. Установи текущую версию из `dist\...Setup-0.1.0.exe`.
2. Выложи файлы версии `0.1.1` на сервер обновлений.
3. Запусти установленное приложение → через несколько секунд вверху баннер → «Перезапустить и установить».

## Нюансы

- Инсталлятор **не подписан** — на новых машинах возможно предупреждение SmartScreen (лечится подписью сертификатом; тогда и обновления будут «тихими»).
- `latest.yml` содержит контрольные суммы — не редактируй его вручную, всегда бери из `dist\` после сборки.
